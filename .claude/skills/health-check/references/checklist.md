# 健康診断チェックリスト（診断対象の詳細）

各項目について「状態（🟢 良好／🟡 要改善／🔴 要対応／⚪ 該当なし）」＋所見を出すこと。

## 1. PC 全体のディレクトリ階層

- ホーム直下〜プロジェクト群・ドキュメント・ダウンロード等の散らかり具合
- 命名規則の不統一（大文字小文字・区切り文字・日本語/英語の混在など）
- 深すぎる／浅すぎる階層
- 重複・放置フォルダ（同名プロジェクトの複製、`old` / `backup` / `コピー` 系）
- プロジェクトの置き場所の一貫性
- ※構造（ツリーと命名）のみ診断し、ファイルの中身は不用意に開かない

## 2. CLAUDE.md

- `~/.claude/CLAUDE.md`（ユーザー全体）と各プロジェクト直下の両方を確認
- 内容・粒度・トークン量・重複
- 常時読むべきでない「手続き」が混ざっていないか（→ skill へ移すべき）

## 3. .claude/rules/

- パススコープの妥当性（ルールが適用されるパスと内容が合っているか）

## 4. スキル `.claude/skills/*/SKILL.md`

- description（発火トリガー）の精度 — 想定した場面で確実に発火する書き方か
- 本文の粒度（長すぎ／短すぎ）、references への分割
- スキル間の重複
- 未発火リスク（description が曖昧・他スキルと競合）
- 旧 `.claude/commands/` からの移行状況

## 5. サブエージェント `.claude/agents/`

- 役割分担が明確か
- tools の read-only 制限（調査系エージェントに書き込みツールを渡していないか）
- model 指定（タスクに対して過剰／過小でないか）
- memory の活用

## 6. フック（settings.json 内）

- PreToolUse 等のガードレール有無（危険コマンドのブロックなど）
- フォーマッタ／通知の自動化（PostToolUse / Stop フックなど）

## 7. output-styles

- 定義の有無と、用途に合っているか

## 8. MCP 設定（.mcp.json / settings）

- 未使用サーバー
- 重複登録（user / project 両方に同じサーバーなど）
- 権限過多（不要な書き込み系ツールの常時有効化）

## 9. settings.json と permissions

- user / project / local / managed 各スコープの内容と役割分担
- permissions（allow / deny / ask）の妥当性 — 緩すぎ／厳しすぎ／プロンプト頻発

## 10. プラグイン／マーケットプレイス

- 個別設定（skills / agents / hooks の組）を plugin 化して複数プロジェクトで再利用できる余地

## 11. モデル運用

- タスク別の使い分け（Fable / Opus / Sonnet / Haiku）
- effort / thinking の方針（重い設計タスクと軽い定型タスクの切り替え）

## 12. コンテキスト効率

- /compact の運用
- always-on（CLAUDE.md・rules 等、常時読み込まれるもの）の肥大化
- subagent へ委譲すべき重い処理（大規模検索・ログ解析など）

## 13. 自動化

- スケジュール実行／CLI ワンショット（`claude -p`）／GitHub Action／pre-commit 連携の有無

## 14. Git・ワークフロー

- コミット規約、レビュー、承認フロー

## 日々の活用の見直し

- 現状の使い方から、超効率的かつ最大火力（並列化・自動化・コンテキスト節約）を出す改善点
- 反復作業のうち スキル化／フック化／サブエージェント化 すべきもの
- 「毎回言っている指示」で CLAUDE.md や output-style に移すべきもの
